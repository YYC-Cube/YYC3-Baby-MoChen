### T-06 静态产物 `/api` 纯净性（字节级）

```powershell
node -e "const fs=require('fs'),p=require('path');function walk(d){for(const e of fs.readdirSync(d,{withFileTypes:true})){const f=p.join(d,e.name);if(e.isDirectory())walk(f);else{const b=fs.readFileSync(f);if(b.indexOf(Buffer.from('/api'))>=0)console.log('HIT',f);}}}walk('dist');console.log('done')"
```

结果：**0 命中**。大小写不敏感扫描同样 0 命中。

> 方法学备注：先前用 PowerShell `Select-String` 扫描二进制 JPEG 时出现 1 次误报，经 Node 字节级复核为解码假阳性。**CI 的 GNU `grep -rq "/api" dist/` 以字节方式匹配，不会误报，该断言有效。**

## 八、对 CI 门禁的评价

| 门禁 | 现状 | 评价 |
| --- | --- | --- |
| 静态构建 | 有 | 有效 |
| `/api` 纯净性 | 有（`grep -rq`） | 有效；建议改为 `grep -rIq` 并限定 `*.js/*.css/*.html`，消除二进制噪声 |
| 服务端构建 | 有 | 有效 |
| `/healthz` 冒烟 | 有 | 有效但覆盖极窄（只验证进程活着） |
| lint / unit / e2e | **无** | 本次审核发现的 P1-01/P1-02 这类问题完全无法被拦截 |
| 敏感资产守卫 | **无** | P0-02 可再次发生 |

## 九、结论

- 构建链路中「静态形态」和「服务端单文件」是可靠的；「全栈主构建」在 Windows 不可用。
- 服务端在无库场景的 fail-closed 行为与路径穿越防护经实测成立，安全底线可信。
- 登录闸导致静态形态整体不可用，是本轮最严重的功能缺陷（已由 UI 冒烟闭环证实）。
- 数据层、鉴权、照片、限流的真实行为仍缺证据，需在具备 MySQL 的环境补测后再给出最终质量结论。
