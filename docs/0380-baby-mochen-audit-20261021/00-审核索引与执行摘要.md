### 2.2 关键结论（先看这里）

1. **静态形态当前不可用（P0）**：`__SHARED_BACKEND__=false` 的静态产物没有注入式登录，`authReady` 恒为 false，登录闸永久停在 `unavailable`，应用主体（`gate !== "in"`）永不渲染。实测浏览器只能看到「登录服务暂时不可用」+「重试」，无底部导航。这与 README 第 431 行宣称的公网演示站 `mc.yyc3.vip` 直接冲突。
2. **私人照片随构建进入发布物（P0）**：`public/沫辰-10.02/` 下 3 张原图共 10.57MB，源码零引用，Vite 会原样复制到 `dist/` 并随 Pages 发布；`.gitignore` 未排除。
3. **仓库状态与既有文档严重不符（P0）**：`main` 分支 0 个提交、全部文件 untracked、仅 1 个远程 `origin`；既有 `docs/0379-*` 中「基线 8784f3d、双远程已推送、总分 90」均无法在工作区复现。
4. **多人同步会静默丢数据（P1）**：409 冲突时用服务端 payload 整份覆盖本地，并置 `skipPushRef` 跳过回推，本地刚录入的记录不可恢复。
5. **登录闸存在死锁路径（P1）**：`authReady=true` 但 `serverSignInUrl=null` 时，`startSignIn()` 不跳转返回 null，`gate` 永远停在 `redirecting`，无错误提示、无重试入口。
6. **Windows 下主构建命令不可用（P1）**：`build` / `build:kimix` 依赖 POSIX 环境变量前缀，实测 `npm run build` 直接报 `'BUILD_TARGET' is not recognized`。
7. **工程保障缺失（P1）**：无 lint、无单元测试、无 E2E；CI 仅做构建、纯净性与 `/healthz` 冒烟。
8. **性能主矛盾是字体而非 JS（P2）**：`noto-sans-sc.woff2` 单文件 7.42MB 且无 `unicode-range` 分片；JS 产物 339KB（gzip 105.85KB）属可接受区间。
