## 关键经验沉淀

1. **Push Protection 是最后防线**：历史密钥（阿里云 AK）由 GitHub 拦截暴露，filter-repo 净化 + 强推闭环；文档示例一律占位符。
2. **托管环境假设须实测**：NAS（fnOS）无 docker CLI、SSH 非标端口 9557、MariaDB 为原生安装——方案设计前先探明。
3. **boot.js 是构建产物**：位于 `dist-server/`（`npm run build:server` 产出），仓库根无此文件；esbuild 自包含免 node_modules。
4. **后台进程需 nohup + disown**：普通 `&` 随终端回收导致「连接被拒」假象。
5. **家庭隐私资产隔离**：实拍照片不入公开仓库（f2af9bc），历史重写后引用层与对象层均已清除。
6. **三方对齐方向**：NAS git 停旧线时勿盲目 pull（会把照片带回合并结果），应强推新线 + 服务端 gc。
7. **docker-proxy 端口占用须全量排查**：`ss -tln` 显示 3000/3100 被 fnOS 托管容器按特定 IP 绑定（非 0.0.0.0），curl 单 IP 探测会误判空闲；本次落位 3030。
8. **远端写脚本禁用未引号 heredoc**：`<<EOF` 会本地展开 `$VAR` 致脚本损坏；改为仓库资产 + scp 分发（deploy/start.sh），彻底规避。
9. **rsync boot.js 后必须重启进程**：esbuild 产物内联全部依赖，但内存中旧代码不会热加载；kill 后看门狗 ≤5 分钟自愈，或手动 `bash start.sh`。
10. **GitBucket 匿名卷会在系统更新重建容器时遗弃**（10-22 实证）：fnOS 00:33 更新重启后 compose（/tmp/mig/gitbucket）重建容器挂新匿名卷，旧卷（真实数据）被遗弃致 origin 404；按 mtime+体积定位旧卷，停机 rsync 覆盖回当前卷即恢复，未丢数据。NAS 每次系统更新后须核验 `git ls-remote origin`。
